# Folder39 - Dynamic Security Group List

This Terraform project demonstrates how to create multiple ingress rules for an AWS security group using a `dynamic` block and a list of port objects.

## Purpose

The configuration defines a security group with several allowed inbound ports and uses a reusable variable to keep the rules easy to manage and extend.

## Files

- `main.tf` - creates the `aws_security_group` resource and defines the `dynamic "ingress"` block
- `variables.tf` - declares the `allowed_ports` variable with a list of objects
- `provider.tf` - configures the AWS provider for the `us-east-1` region
- `version.tf` - sets the Terraform and AWS provider version requirements

## Example variable

```hcl
allowed_ports = [
  { description = "SSH", from_port = 22, to_port = 22 },
  { description = "HTTP", from_port = 80, to_port = 80 },
  { description = "HTTPS", from_port = 443, to_port = 443 }
]
```

## What the infrastructure creates

- One AWS security group named `my-sg-list`
- Inbound rules for:
  - SSH on port 22
  - HTTP on port 80
  - HTTPS on port 443
- An outbound rule allowing all traffic (`0.0.0.0/0`)

## Usage

```bash
terraform init
terraform validate
terraform plan
terraform apply
```

## Lesson learned

This exercise shows that Terraform configuration can stay clean and scalable when repeated infrastructure blocks are generated from structured input data. Instead of manually writing one ingress rule per port, we define the ports as a list of objects and let the `dynamic` block build the security group rules automatically.

This approach is especially useful when you want to:

- add or remove ports easily
- keep security rules consistent
- reduce duplication in configuration files
- make future updates faster and less error-prone

## Conclusion

The `dynamic` block is an effective way to manage repeated AWS resources or nested blocks without hardcoding each rule. In this project, the security group remains easy to update because the rule definitions are centralized in the `allowed_ports` variable.

This demonstrates a core Terraform best practice: use variables and iteration to make infrastructure configurations more maintainable and reusable.

## Troubleshooting

### 1. `terraform validate` fails

Check for:

- missing required variable values
- invalid object structure in `allowed_ports`
- syntax errors in the `dynamic` block or resource definition

### 2. Security group rules do not match the expected ports

Verify that:

- each item in `allowed_ports` includes `description`, `from_port`, and `to_port`
- the values are numbers, not strings
- the rule is being generated by the correct `dynamic` loop

### 3. AWS provider or Terraform version errors

Ensure:

- Terraform is installed and compatible with the version in `version.tf`
- the AWS provider version matches the requirement
- your AWS credentials are configured correctly

### 4. Terraform plan/apply hangs or fails due to AWS permissions

Check that your AWS IAM user or role has permission to:

- create security groups
- manage ingress/egress rules
- access the target AWS account and region

## Notes
